# 科研PPT设计规范

来自个人页面结构库的设计建议。原型选择先满足语义关系；字体、颜色及密度按用户提供的实际模板调整。

## 从模板中归纳的个人科研PPT设计规范

### 1. 建库单位：主关系、信息角色和阅读路径

一个原型应由“信息关系＋区域分工＋视觉编码”定义。配色不同、照片不同、章节高亮不同，不足以形成新原型；证据角色改变、主阅读路径改变，则应考虑新原型或明确变体。

本次合并规则如下：

| 同组案例 | 合并理由 | 仍需保留的差异 |
|---|---|---|
| P05／P21／P22 | 都用同构阶段表达演进 | 双行跨域类比、单行系统演进、有无收束条 |
| P13／P14／P25 | 多支路各自处理后在明确位置汇合 | 双通道建模、双指标诊断、多路检索；输出数量不同 |
| P18／P29 | 锁定视觉口径比较条件变化 | 参数条件一图一值；消融条件在每项指标图内比较 |
| P19／P20 | 结果图与解释表共同识别同一对象 | 分类语义映射、关键对象排序 |
| P26／P27 | 通过类别、数量、示例解释数据构成 | 左来源右表、全宽统计表 |
| P33／P34 | 三类定量证据支撑一个判断 | 选型决策、算法质量验证 |
| P36／P41 | 同一目录母版、仅当前章不同 | 高亮章节编号 |
| P38／P39／P40 | 一项功能配一幅主要界面 | 查询、感知、规划的输入输出各不相同 |

### 2. 建立三层页面骨架

普通研究内容页优先采用以下三层：

1. **定位层：**章节或页面主题，让观众知道讲什么。
2. **解释层：**图、表、结构和必要标签，让观众理解关系。
3. **落点层：**本页结果、研究问题或下一步依据，让观众知道应记住什么。

P02、P09、P28把落点做成底部通栏；P17、P18、P33、P34把结论提前放在图上方；P31在对比框内部完成差异解释。落点不必每次都加色条，也不必同时在顶部、图内、底部重复三遍。

连续研究进展页可以保留简短章节身份，但**本页具体发现或方法主题应成为主要标题**。原稿P10–P35较长的章节标题持续占据横幅，导致不同页面需要靠正文辨认。个人系统可改为“小章节标签＋具体页题”，提高检索和回看效率。

### 3. 关系到视觉的编码规则

| 内容关系 | 视觉必须表达什么 | 建议结构与案例 | 禁止的误读 |
|---|---|---|---|
| 并列 | 等级一致、可交换顺序 | 同宽模块、同级标题；P07 | 把同级维度连成强制流程 |
| 分类 | 上位集合、统一划分标准 | 分类表或模块集合；P06、P27 | 混合方法、指标、场景作为同一分类 |
| 总分 | 统领项与所属分项 | 上总下分；P09的上半部 | 把普通页标题视为足够的总分证据 |
| 层级 | 多级包含与不同信息粒度 | 嵌套容器、分层带；P37 | 仅凭上下摆放判层级 |
| 流程／IPO | 起点、步骤、变换、终点 | 定向链路、箭头标动作；P12、P25、P32 | 把所有箭头都解释为因果 |
| 时序／演化 | 时间或状态变化不可随意换序 | 时间线、同构阶段；P02、P05、P21 | 把时间先后视为充分的因果证明 |
| 问题—解决 | 应对针对哪个问题 | 场景—瓶颈—方案；P30 | 把P10的研究提问写成已解决成果 |
| 映射 | 两边对象能够对应 | 同色、同编号、对齐；P11、P19、P24 | 把匹配关系说成影响关系 |
| 汇聚 | 多路贡献与合并位置 | 分支合流、共同底座；P13、P14、P09 | 只摆在一起却没有共同结果 |
| 发散 | 从哪个中心向哪些输出展开 | 输出分支；P14策略区、P42执行区 | 用向外射线掩盖实际包含或映射含义 |
| 对比 | 共用维度、尺度和基准 | 对称栏、对照表、同构图；P18、P31、P34 | 两张不同图并排就叫对比 |
| 观点—证据 | 每项证据支持哪个判断 | 结论＋证据组合；P17、P28、P34 | 图只装饰页面，无法对应主张 |
| 总—分—总 | 末端完成整合或提炼 | 目标—模块—验证；P09、P44 | 最后再写一遍开头 |
| 二维矩阵 | 行、列各有明确语义 | 共用行列标题；P08 | 把任意2×2排版称为矩阵关系 |
| 闭环／反馈 | 输出反馈到前序对象，影响下一轮 | 有标注的外回路；P30局部、P42 | 图画成圆或方法名含“迭代”就判闭环 |

### 4. 视觉权重从信息角色推导

**同级内容采用一致的基础语法。** 三个研究问题用同级标题，实验条件用相同图幅，表格比较共用列，避免某项仅因文案较长而突然变成主角。

**面积可以由解释任务决定。** P04的一主两辅、P12的中间大图、P25的融合节点、P37的核心智能体都说明等逻辑地位与等面积不是一回事。分配更多空间时，要能说清“这里为什么需要被重点理解”。

**每个区域要有明确职责。** 上部讲判断，下部提供证据；左边给对象，右边给解释；底部负责验证或总结。不要让同一块区域同时承担现状、方法、结果、展望四种任务。

### 5. 箭头与边界采用可解释的规则

- 箭头旁优先用短动词或名词说明关系：建模、检索、融合、传递、执行、反馈。
- 同页若有多种流，参考P32给出图例，以线型和颜色共同区分；纯装饰箭头删除。
- 容器框表示归属或阶段边界；虚线通常表示分组、局部区域或辅助关系，需在该页保持一致。
- 总分可用空间包围表达，无须给每个子项都画箭头。
- 双向关系尽量分成两根有标签的单向箭头，例如“提交需求”和“返回方案”，避免含义模糊。
- 汇聚节点应写“融合什么”，反馈线应写“返回什么”，不能只写抽象的“连接”。

### 6. 图表页先定义证据任务

| 要回答的问题 | 优先证据 | 推荐原型 |
|---|---|---|
| 为什么选这个参数？ | 多指标趋势、共同选点 | T16、T17 |
| 输出类别在领域中意味着什么？ | 图中类别与解释表 | T18 |
| 方法整体是否更好？ | 同条件指标表，必要时配分布 | T25 |
| 为什么说复杂情况下更稳？ | 分条件比较及代表案例 | T22 |
| 哪个组件有作用？ | 完整模型与移除条件对照 | T17的消融变体 |
| 随迭代如何改善？ | 迭代曲线、关键变化点 | T26 |
| 是否减轻工作量？ | 与任务直接相关的投入指标及输出质量 | T26，不只展示单一性能曲线 |

图表复用的具体规则：

1. 图例、方法顺序、条件名称跨图一致，优先保留相同方法的固定颜色。
2. 对比图统一坐标和色阶；必须不同尺度时明确标识。
3. 表格写清指标方向、单位、倍率与统计含义，必要时区分均值、波动、最好与最坏情况。
4. 结论只覆盖证据确实支持的范围。红色选中“本文方法”与红色表示“该列最佳”不能混用。
5. 图内短标签负责定位，完整结论移到独立留白区，不遮挡数据、坐标或误差线。
6. 细小原始图无法在投影下读清时，应简化、重绘数据图或局部放大；不要仅把整篇论文图缩小贴入。

### 7. 个人视觉基础参数建议

以下为**拟建立的个人规范**，不是从图片中测得的原稿字号或色值。它们适用于16:9科研汇报，可按会场与显示设备调整。

| 项目 | 建议基线 | 依据与用途 |
|---|---|---|
| 画布 | 16:9 | 原PPT及多数PNG采用宽屏组织；19.png有裁切差异，不据其截图比例改画布 |
| 安全边距 | 左右约4%，底部保留明确留白 | 避免图表、引文和截屏角标贴边 |
| 页面分区 | 普通页可从标题10%、主张15%、主体70%、来源5%起步 | 总比例100%；长图页把主张压短，把空间让给图 |
| 标题字号 | 30–36 pt | 具体页题优先，长章名降为辅助身份信息 |
| 核心判断／模块标题 | 22–26 pt | 建立第二层阅读入口 |
| 正文 | 20–24 pt | 一般保持短句，密度过高先删减或拆页 |
| 图内标签 | 16–20 pt为起点 | 实际投影可读性优先，细密图通过局部放大解决 |
| 来源注释 | 10–12 pt，仅限无需现场逐字阅读的信息 | 不把关键条件藏在小字里 |
| 配色角色 | 深蓝结构色、浅蓝底色、黑灰正文、一个强调色 | 继承原稿稳定的蓝白基调，不要求复制原色 |
| 可选配色值 | 深蓝`#123F79`、浅蓝`#E9F0F8`、强调红`#B51F24`、辅助青`#2D858A` | 作为个人色板起点；辅助青仅在需要区分第二类结构时使用 |
| 字体角色 | 中文采用一套清晰的无衬线字体；公式保留标准数学排版 | 统一比堆叠字体更重要，最终以实际可用字体为准 |
| 模块数量 | 常用2–4个一级模块 | 六类功能可用2×3；更多节点应分组或拆页 |
| 边框与底色 | 浅底＋少量边界，避免每个文字块都套框 | 边界要表达分组，不能只有装饰作用 |

### 8. 图片和系统截图规范

研究对象图负责解释对象，实物照片负责提供场景，界面截图负责展示功能，算法图负责解释关系。选择图片时先确定职责，避免“有图就更专业”的无目的拼贴。

从P03、P15提炼出的规则是：**大图建立空间，小图解释局部，标签直接指向对象。** 从P38–P40提炼出的规则是：**一页一个功能，先说明输入输出，再展示关键界面。** 每张图都应具有可读标题、必要注释和清楚的来源身份。

不要继承截屏边缘、播放器或批注按钮、计时角标等非内容元素。整页图片不适合继续作为个人系统的编辑母版；这里入库的是关系与结构，未来实际制作时应把标题、关系线和关键标签恢复为可编辑对象。

### 9. 优先沉淀的核心原型

若先搭建一个精简的日常科研页面库，建议优先掌握以下八类，其余作为专用变体。选择依据是本次案例中可迁移的逻辑骨架，不是对原页视觉完成度的评分。

| 优先原型 | 最常回答的问题 | 首选参考 |
|---|---|---|
| T07 三个关键问题 | 本研究究竟解决哪些问题？ | P07 |
| T08 现状—局限—趋势矩阵 | 已有工作缺在哪里？ | P08 |
| T09 总目标—三模块—共同验证 | 几项工作如何组成完整研究？ | P09 |
| T10 场景—局限—突破口 | 为什么需要这个方法？ | P10、P30 |
| T13 多路径汇合 | 多种信息如何共同产生结果？ | P13、P14、P25 |

| T28 分层架构 | 系统由哪些部分构成、怎样分工？ | P37 |

背景页补充T02、T03；实验页补充T17、T18、T22、T26；工程演示补充T29；系统展望补充T30、T31；封面、目录、总结使用T01、T27、T32。

### 12. 制作前的八项检查

1. 能否用一句话说出这页唯一要回答的问题？
2. 每个信息块的角色是否明确，是否把不同层级混放？
3. 主关系与逻辑草图能否成立，是否只是按数量套版？
4. 每条箭头、每个容器、每种高亮是否有明确含义？
5. 对比是否共用维度、尺度、单位和实验条件？
6. 每项图表证据是否能支持相邻结论，是否存在遮挡或泛化？
7. 从标题到主体再到落点，是否只有一条清晰的主阅读路径？
8. 投影时关键文字能否读清，是否明确区分结果、解释、计划和展望？

### 13. PNG补库形成的选版与视觉规则

1. **先数逻辑层级，再数卡片。** N01的上层两个块属于同一基础阶段，整页是四阶段；W08是四项能力加三项措施。用分区、容器与一级标题表达层级，不按方框总数命名页面。
2. **章节标题只说明使用位置，不直接决定原型。** 同叫“研究内容”，W10是装置解剖，W12是性能维度，N01是阶段任务。模板名称宜写“装置与部件标注”“三性能卡”等实际组织形式。
3. **分阶段、并列和映射采用不同视觉语法。** 有任务依赖时用定向线并写交付物；同级维度用等权卡；一一映射用共用行或对应编号。N03矩阵的行列语义不能被装饰框替代。
4. **数字必须有角色。** W12的大数值可形成性能卡，但需写单位、基准与条件；W02顶部总量应与表格选录及贡献角色区分。阶段编号、性能指标和成果条数不使用同一种强调语法。
5. **主图的职责决定它能支撑什么。** W01讲机制、W10讲组成、W11讲资源、W04讲模型表达。需要证明性能时，另补能够对应主张的实验数据；不要因都是图片就互换职责。
6. **关联图先减线，闭环图先定义反馈。** N11—N13的环带和多向线可借作结构草图；重建时让每条线可解释。若说不清测什么、传给谁、改变什么，就不使用闭环原型。
7. **用固定区域维持整套PPT的一致性。** 蓝白系列普遍采用顶部标题与细分隔线、标题下主张条、中部主体、底部落点。可沿用这套区域职责；并非每页都需同时保留四区，重复主张或长底部口号应删除。
8. **色彩编码跟随角色。** 深色标题条组织模块，浅底区分组，红色只用于问题、关键结果或一个指定强调角色。同页不要让红色同时表示风险、创新点、模块类别和全部结论。
9. **图片数量不决定论证强度。** N02、W06、W07含密集科研拼图，可提取“主图＋辅图”分组方式；复用时保留最能说明任务的一组，并给其余图降级或拆页，不继承无法投影阅读的小字。
10. **把来源、原型和变体分开维护。** 原型ID表示稳定逻辑结构，N／W编号表示来源实例；左右镜像、三栏改四栏可作为变体，核心角色改变才考虑新增类型。重复截图不增加类型，同题不同组织方式则保留独立案例。

今后每新增一张PNG，在选用索引中加一行，并在逐图记录中注明原型、结构变体、适用条件与识别限制。判断是否新增原型时，检查现有类型能否保留该页的主关系和阅读路径；能保留就补案例，保留不了才新增。

**本库的核心设计规范：用空间组织表达语义关系，用视觉权重强调页面意图，用证据支撑落点。** 具体图像、装饰和主题色可以变化，信息角色与关系不应随模板变化。
