# 逐页汇报卡片规范 v1.0

## 用途与边界

汇报卡片是一次汇报的页级内容计划；模板卡片是模板库中某种版式的说明。先独立规划内容，再匹配模板，避免从空白框的数量反推研究逻辑。

用户可直接提供自然语言、论文、Word、Markdown、图表和已有PPT。AI负责整理；[需求模板](../assets/report-brief.md)是可选输入格式。文字不充分时列出缺口，不为填满字段补造事实。

## 两次填写同一张卡片

1. **内容规划：**确定稳定页ID、问题、核心主张、内容模块、关系、证据及衔接。这个阶段模板ID留空。
2. **模板匹配：**检索实际模板，填入模板ID、槽位对应、调整项和待验证状态。不合适时拆页或重建，不强行填满模板。

按 [卡片模板](../assets/slide-cards.md) 生成 `逐页汇报卡片.md`。同一报告用 S01、S02 等稳定ID；重排只改页序，拆页分配新ID。已认可的页面保留其决策，只调整受新材料影响的部分。

## 必要字段及填写含义

| 字段 | 要求 |
|---|---|
| 表达目标 | 这一页让听众回答什么问题；与页面主题区分 |
| 核心主张 | 一句话；允许是研究问题、方法说明或待验证假设，不强迫写成实验结论 |
| 内容模块 | 每块有角色、实际文案、证据来源；用 M1 等标识供槽位映射 |
| 关系与结构 | 一项主关系，可有辅助关系；说明箭头是信息流、处理依赖、论证支持还是其他关系 |
| 证据状态 | 已提供／待补充／假设／演示虚构；分别标注，不能把方法设想当验证结果 |
| 素材引用 | 指向具体文件、页码、表格、段落ID；缺少原图时不可填写虚构路径 |
| 模板匹配 | 从实际库读取模板ID；注明候选或已核对，写明取舍与调整 |
| 槽位映射 | 内容模块对应模板中的哪个区域；未解析对象ID时只写语义区域，不编造对象ID |
| 状态 | 内容待补充／可制作／已生成待检查／已检查；分别说明逻辑、版式、渲染是否检查 |

页级描述可预估字数与图表数量，但当前库没有精确的文本容量模型，不把建议字数当作脚本测量结果。只有实际渲染后才能确认溢出、遮挡和可读性。

## 用户参与及交付

- 用户负责研究事实与偏好，AI承担结构分类、卡片起草和模板推荐。卡片不是要求用户完成的问卷。
- 只请求卡片时交付Markdown；请求完整报告时继续制作，不自动增加审批关卡。
- 用户只问单页选版时，精简为目标、关系、内容/证据、模板与调整四项即可。
- 不把卡片全文塞入PPT备注；最终备注按用户需求写讲述提示、引用和可选模板ID。
- 模板元数据继续遵循九字段约定。本次卡片功能不改变PPT原件、不新增自动填充或视觉检索能力。

## 测试与验收

先使用 [测试输入](../examples/logic-test-input.md) 生成卡片，再参照 [验收参考](../examples/logic-test-expected.md) 检查。参考拆页不是唯一答案；判断表达关系、证据边界、模板适配是否成立，不要求逐字一致。
