# 页面原型与选用规则

41类原型。先按T编号或逻辑关系检索；具体页面用PPT备注及catalog.json中的稳定ID定位。P/N/W是历史案例编号，图片已留空，使用自己的证据材料。

<a id="t01"></a>
## 页面类型1：中央主题与底部身份封面

- **名称：**中央主题与底部身份封面（T01）。
- **逻辑关系：**主次；研究题目是主信息，报告人与机构是身份信息。
- **逻辑结构：**`主题 > {报告人、机构、时间}`。
- **适用场景：**学术报告、开题、答辩、项目汇报的开场。
- **视觉结构：**顶部活动信息；中央两行大标题；底部通栏色块承载身份信息。
- **案例来源：**P01。
- **设计原则：**通过字号与面积差建立唯一阅读中心。长标题按语义断行，底部色带把背景信息集中成稳定的辅助区域。
- **复用边界：**封面不承担研究结构说明。底部信息不要贴边；机构标识替换为自己的合法素材，截图角标不继承。

<a id="t02"></a>
## 页面类型2：时间线证据与需求收束

- **名称：**时间线证据与需求收束页（T02）。
- **逻辑关系：**时序为中部骨架，整页采用总—分—总；阶段事件共同支撑需求判断。
- **逻辑结构：**`阶段判断→{T1→T2→…→Tn〔时间〕}→新需求`。
- **适用场景：**研究背景、技术发展、政策沿革、工程需求变化。
- **视觉结构：**顶部一句判断；中部水平时间轴，上下交错放事件与对象图片；底部通栏结论。
- **案例来源：**P02。
- **设计原则：**共用时间轴建立先后，同一对象序列占同一侧，末端总结回答“这些变化为何与本研究有关”。
- **复用边界：**事件先后不直接证明因果。节点过多时保留关键转折，避免把每一年都填满。

<a id="t03"></a>
## 页面类型3：整体对象与局部标注

- **名称：**整体对象与局部标注页（T03）。
- **逻辑关系：**整体—部分为主，部件与约束／指标之间存在映射。
- **逻辑结构：**`整体⊃{部件i}`，`部件i↔{位置、问题、指标}`。
- **适用场景：**研究对象介绍、设备结构、解剖结构、材料分区、实验装置组成。
- **视觉结构：**一张大幅分解图或实物图；外围引线标注；局部用色点定位；角落集中数量级信息。
- **案例来源：**P03。 新增PNG：W10。
- **设计原则：**让文字直接附着于空间对象，减少“看图后再找列表”的往返；少量高亮标记建立关注点。
- **复用边界：**图上的指示线表示定位，不表示流程；必要时把组成标注和故障标注分成两页。
- **PNG结构变体：**W10为双剖面＋左右功能卡，仍以部件的空间位置与功能标注为核心。

<a id="t04"></a>
## 页面类型4：一主两辅挑战展开

- **名称：**一主两辅挑战展开页（T04）。
- **逻辑关系：**总体挑战下的三个方面是并列，视觉表达具有主次。
- **逻辑结构：**`挑战⊃{A,B,C}`；画面权重为 `A>B≈C`。
- **适用场景：**复杂工程背景、三类难点，其中一类需要大场景解释。
- **视觉结构：**顶部总述；左侧一幅大图；右侧上下两块辅助证据；三块各有短标题。
- **案例来源：**P04。
- **设计原则：**按解释所需空间分配面积，大图提供整体环境，小图解释局部困难，避免把三种不同尺寸的证据硬塞进三等栏。
- **复用边界：**面积大不代表逻辑上级。只有确有传递关系时才保留块间箭头。

<a id="t05"></a>
## 页面类型5：阶段演进对照

- **名称：**阶段演进对照页（T05）。
- **逻辑关系：**演化／递进为主，阶段间使用相同维度对比；双行版本还具有跨领域类比。
- **逻辑结构：**`S1→S2→S3〔演进〕`；双行变体为 `领域A的三阶段↔领域B的三阶段〔类比〕`。
- **适用场景：**技术范式变化、传统方法到新方法、人工到智能化、行业借鉴。
- **视觉结构：**三个同尺寸阶段区横排；每阶段保持同一组件顺序。可用两行照片对照，或三栏系统图；收束变体增加底部结论。
- **案例来源：**P05、P21、P22。
- **设计原则：**重复相同视觉语法，让变化集中在新增能力与关系上。先看出“变了什么”，再读内部细节。
- **复用边界：**演进箭头不同于单次业务流程。P21、P22作为同一原型的两个状态保存，不重复建库。

<a id="t06"></a>
## 页面类型6：原有系统与功能单元拆解

- **名称：**原有系统与功能单元拆解页（T06）。
- **逻辑关系：**整体—部分、功能分类，并对比两种组织方式。
- **逻辑结构：**`原组织方式 vs {功能单元1…6}`，`系统⊃六类功能单元`。
- **适用场景：**系统解耦、模块化设计、平台功能划分、单体系统向模块系统转型。
- **视觉结构：**左侧原系统大图；右侧六块功能卡按两行三列排布；共享连接方式放在中间横带。
- **案例来源：**P06。
- **设计原则：**左侧解释原来的耦合，右侧展示重组后的分工；共用连接条避免重复说明基础设施。
- **复用边界：**六个模块并非六步流程；网格不自动构成二维矩阵，除非行列各有独立含义。

<a id="t07"></a>
## 页面类型7：三个关键问题展开

- **名称：**三个关键问题展开页（T07）。
- **逻辑关系：**总分＋并列；各问题内部可包含挑战—应对、状态关系或反馈机制。
- **逻辑结构：**`总议题→{Q1,Q2,Q3}〔展开〕`，每栏为 `问题表述＋解释图＋研究任务`。
- **适用场景：**关键科学问题、三项研究难点、研究任务定义。
- **视觉结构：**顶部统领提问；下方三等宽纵栏，标题、短关系链、示意图、任务句依次对齐。
- **案例来源：**P07。
- **设计原则：**同级问题使用同级标题，统一栏目顺序，观众可横向扫读对应位置；局部不同图形服务于各自问题。
- **复用边界：**有三个框不等于三个步骤。原稿块间箭头不应直接照搬，需先确定是否真的有依赖。

<a id="t08"></a>
## 页面类型8：现状—局限—趋势矩阵

- **名称：**现状—局限—趋势矩阵页（T08）。
- **逻辑关系：**二维矩阵为主；每列内部是现状到缺口再到应对方向。
- **逻辑结构：**`研究方向×{现有研究、核心局限、研究趋势}`。
- **适用场景：**文献综述、研究现状、技术缺口定位、研究方向论证。
- **视觉结构：**三列主题，左侧共用行标签；同类行同色；底部用简化链概括能力发展。
- **案例来源：**P08。 新增PNG：N03。
- **设计原则：**横向比较同一评价项，纵向看同一方向的缺口及应对。共用行标签减少重复文字。
- **复用边界：**不能把每格都写成段落；三列必须共用评价口径。底部发展链与上部矩阵采用不同箭头语义。
- **PNG结构变体：**N03为三技术方向×现状／挑战／探索方向矩阵，另加窄侧栏补充概念。

<a id="t09"></a>
## 页面类型9：总目标—三模块—共同验证

- **名称：**总目标—三模块—共同验证页（T09）。
- **逻辑关系：**总—分—总为主，三项工作共同汇聚到验证平台；模块之间还可有依赖。
- **逻辑结构：**`G→{M1,M2,M3}→V`，即 `1→3→1`；横向 `M1→M2→M3`需单独说明依赖。
- **适用场景：**研究内容总览、技术路线概览、基金申请总体方案。
- **视觉结构：**顶部总目标；中部三块研究模块；每块底部输出标签；三根向下箭头落到横跨全页的验证区。
- **案例来源：**P09。
- **设计原则：**每块说明“做什么、产出什么”，底部回答“如何共同验证”。模块同宽表示同属研究内容，底座横跨全宽表示共同承接。
- **复用边界：**底部是验证安排，不是已经取得的结果；不能仅为了凑总—分—总再重复总目标。原稿内部细节较多，个人版宜保留一级结构。

<a id="t10"></a>
## 页面类型10：场景—局限—研究突破口

- **名称：**场景—局限—研究突破口页（T10）。
- **逻辑关系：**问题推导；当右端已有明确应对方法时，构成问题—解决。
- **逻辑结构：**`应用需求→现有方法局限→研究问题／解决思路`。
- **适用场景：**方法章节引入、研究动机、创新点依据。
- **视觉结构：**左侧真实场景，中间旧方法或知识壁垒，右侧高亮研究问题／新方法；顶端用一句话串起动机。
- **案例来源：**P10（落点是问题）、P30（落点是方案）。 新增PNG：N19、N24。
- **设计原则：**三个区域承担不同语义角色，阅读顺序直接对应论证顺序；右侧使用较独立的色区突出研究切入口。
- **复用边界：**P10只有问题提出，不能标成已经解决；三块横排不属于三个同级研究模块。
- **PNG结构变体：**N19用横向“构筑—瓶颈—策略”；N24用“需求—技术—价值”。都由问题角色推动阅读，不因等宽而归为并列。

<a id="t11"></a>
## 页面类型11：抽象概念到应用对象映射

- **名称：**抽象概念到应用对象映射页（T11）。
- **逻辑关系：**映射为主，辅助说明概念适用性。
- **逻辑结构：**`抽象表示↔工程对象〔建模对应〕`。
- **适用场景：**把数学模型、网络、概率图、控制概念引入具体科研对象。
- **视觉结构：**左侧概念图与少量定义；中间带动词的粗箭头；右侧真实或示意应用场景。
- **案例来源：**P11。 新增PNG：W04。
- **设计原则：**抽象与具体各占一个清晰区域，箭头上的“建模／表征”解释两者如何联系。
- **复用边界：**“概念可用于该对象”不等于实验效果已被证明。若需要逐元素解释，应增加同色编号映射。
- **PNG结构变体：**W04把物理规律映射到模型约束；有方向的嵌入可用单向箭头，不必沿用双向对应线。

<a id="t12"></a>
## 页面类型12：语义—结构—特征转换

- **名称：**语义—结构—特征转换页（T12）。
- **逻辑关系：**输入—处理—输出；规则与结构、结构与特征之间是转换映射。
- **逻辑结构：**`{规则1,规则2,规则3}→结构表示→特征向量`，可简记 `N→1→1`。
- **适用场景：**特征工程、图建模、知识表示、数据编码方法。
- **视觉结构：**左侧纵排规则样例，中间较大的结构图，右侧窄幅矩阵；箭头标注转换动作。
- **案例来源：**P12。 新增PNG：N05、N09。
- **设计原则：**各阶段用与数据形态相匹配的视觉对象，既表现步骤，也表现输入输出的变化。
- **复用边界：**中间结构占更大面积是解释权重差异；左侧多条规则是并列输入，不是先后执行的三个步骤。
- **PNG结构变体：**N05为物理模型—特征—信息表示，N09为测量信号—校正／识别—测量量；均需核对真实依赖，不能只因左右排列就认定流程。

<a id="t13"></a>
## 页面类型13：多路径汇合方法

- **名称：**多路径汇合方法页（T13）。
- **逻辑关系：**多路径汇合为主，各支路可有自己的处理步骤。
- **逻辑结构：**P13为 `1→2→1→结果`；P14为 `2→1→3〔策略展开〕`；P25为 `多路查询与证据→融合→回答`。
- **适用场景：**多源融合、结构与属性联合建模、多指标诊断、检索增强生成。
- **视觉结构：**分支区、汇合点、输出区分明；两支路可上下排，多路检索可上下分工；汇合箭头集中于一个明确对象。
- **案例来源：**P13、P14、P25。 新增PNG：N25。
- **设计原则：**观众必须同时看清“各路贡献什么”和“在哪里合并”。分支同级，融合节点拥有更高视觉权重。
- **复用边界：**不能只把几个箭头指向一个框就称融合，要标注被融合的信息。原稿复杂细节可留到后续分解页。
- **PNG结构变体：**N25仅借多来源分支—合并—输出的骨架。其原图标题、正文和流程内容不一致，作为研究路线优先参考P13、P14、P25。

<a id="t14"></a>
## 页面类型14：场景大图与工序定位

- **名称：**场景大图与工序定位页（T14）。
- **逻辑关系：**整体—部分为主，辅以流程与场景—活动映射。
- **逻辑结构：**`实验系统⊃{站位A,站位B}`；`工序1→…→工序n`定位在场景周边。
- **适用场景：**实验平台、验证场景、产线、复杂装置与测试流程介绍。
- **视觉结构：**左侧大幅平台图；虚线圈定子区；上、下或侧边布置工序条；右侧少量局部实物与特征。
- **案例来源：**P15。
- **设计原则：**观众先建立空间坐标，再理解工序发生位置；局部照片回答“平台有什么代表性”。
- **复用边界：**工序条绕着图走只是节省空间，不自动形成闭环。空间边界与流程方向应使用不同线型。

<a id="t15"></a>
## 页面类型15：全局网络与局部实例

- **名称：**全局网络与局部实例页（T15）。
- **逻辑关系：**整体—部分、主次；局部实例解释复杂全局对象。
- **逻辑结构：**`全局G⊃局部g`，`规模说明＋G＋g`。
- **适用场景：**大规模网络、点云、空间分布、系统结构、复杂模型展示。
- **视觉结构：**左侧全局大图，右侧稀疏局部图，关键规模数字紧邻主图。
- **案例来源：**P16。
- **设计原则：**全局图说明复杂程度，局部图说明可理解的连接结构，避免把密集节点全部当正文阅读。
- **复用边界：**原页局部对应位置不够直观。复用时在主图中圈出区域，并用连线或同色编号对应右图。

<a id="t16"></a>
## 页面类型16：多指标证据矩阵

- **名称：**多指标证据矩阵页（T16）。
- **逻辑关系：**评价维度＋观点—证据；多个指标共同支持一个参数选择。
- **逻辑结构：**`{E1,E2,E3,E4}→C〔支撑〕`，即 `4→1`。
- **适用场景：**参数选择依据、多目标评估、从多个维度解释性能。
- **视觉结构：**顶部结论；中部四幅图按2×2排布，图外使用醒目的指标名。
- **案例来源：**P17。
- **设计原则：**各图等尺寸意味着同级证据；指标名称帮助先建立评价框架，再读曲面或数值。
- **复用边界：**2×2摆放本身不是二维矩阵逻辑。各图应标明优劣方向和被选择的参数位置，避免只靠正文宣告结论。

<a id="t17"></a>
## 页面类型17：条件变化下的同构图对照

- **名称：**条件变化下的同构图对照页（T17）。
- **逻辑关系：**对比为主，比较结果支撑参数选择或组件作用解释。
- **逻辑结构：**`同一对象×不同条件→差异判断`；P18为四种参数条件，P29为多个消融条件在三个指标上的表现。
- **适用场景：**超参数敏感性、消融实验、不同工况、不同处理方法效果对照。
- **视觉结构：**一行多幅同构图；参数图可一条件一幅，消融图可一指标一幅、图内比较多个条件；顶部结论，底部短解释。
- **案例来源：**P18、P29。
- **设计原则：**锁定其他视觉变量，只让关注的条件变化。统一图例、顺序、坐标或色阶，使差异可以直接比较。
- **复用边界：**参数值与消融项不是时间阶段。不能因折线相连就解释为动态流程；离散条件也可改用点图或柱图。

<a id="t18"></a>
## 页面类型18：结果图与解释表对应

- **名称：**结果图与解释表对应页（T18）。
- **逻辑关系：**映射为主；结果图、解释表共同支撑研究发现。
- **逻辑结构：**`模型输出i↔语义解释i`；排名版本为 `拓扑特征↔指标排序→关键对象`。
- **适用场景：**聚类结果解释、社区识别、特征重要性、关键节点、定量结果的领域解释。
- **视觉结构：**图在上、解释表在下，或左图右表；表格重复图中的类别编号、颜色或对象名称。
- **案例来源：**P19、P20。

- **复用边界：**表格不宜堆满全部节点编号；口头汇报保留主要类别或前几名，完整明细放附录。

- **复用边界：**原页多条线交叉、示例文字偏多。复用时先理顺主链，再叠加两到三个问题标记，避免把所有区域都标红。

- **案例来源：**N21、N27、W01、W06；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**把空间优先分给需要观察的对象，再用短句引导观众看重点。图内标号与侧栏标号对应时，阅读路径会比大段说明更清楚。
- **复用边界：**机制示意、流程图、实验结果承担不同角色；示意图不能单独证明性能优越。与T29的可运行界面演示、T18的结果图与数据表对应不同。拼图较多时应分组并标注各子图角色。

<a id="t36"></a>
## 页面类型36：双路径汇聚与目标论证

- **名称：**双路径汇聚与目标论证（T36）。
- **逻辑关系：**汇聚；可组合需求论证或问题—解决。
- **逻辑结构：**`{依据A∥依据B}→共同目标〔论证〕，或 问题→{路径A∥路径B}→共同产出〔应对〕`。
- **适用场景：**立项依据、交叉学科切入点、国家需求与学术问题、双路径协同攻关。
- **视觉结构：**顶部交代问题；中部两路同等或明确分工的区域；向右或向下汇聚到研究目标／综合结果。
- **案例来源：**N04、W03、W09；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**两路各自说明独立贡献，汇合区再说明缺一不可的结合价值。共同目标应是对两路的整合，不能只复述页面标题。
- **复用边界：**与T13的信息输入和处理方法不同，本型优先表达为什么做、从哪两路攻关。两栏相邻不等于已经汇聚，需要共同目标或综合产出。政策截图和趋势示意不能冒充实验数据。

<a id="t37"></a>
## 页面类型37：核心—支撑关联图

- **名称：**核心—支撑关联图（T37）。
- **逻辑关系：**核心与支撑要素关联；局部总分，具体方向需另行定义。
- **逻辑结构：**`核心C—{支撑S1，S2，…}〔关联〕；双核心变体 C1—共享支撑—C2`。
- **适用场景：**跨模块概念总览、平台能力关联、核心与外围条件的结构草图。
- **视觉结构：**核心节点位于中央，支撑模块位于周边；双核心可左右对称；容器或分区先区分角色，再画必要连线。
- **案例来源：**N11、N12、N13；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**只保留能解释核心能力的支撑节点，每条线说明关联性质。中心面积突出主题，外围等权节点表现同层支撑；读者应能说清谁支撑谁。
- **复用边界：**本批N11、N12、N13主要作为待整理的图形骨架，非可直接照用的优选模板。环形、双向箭头和中心位置都不证明反馈；若要转为T30必须明确回传内容、接收方和调节动作。删去纯装饰连线后再使用。

<a id="t38"></a>
## 页面类型38：分层问题展开与研究应对

- **名称：**分层问题展开与研究应对（T38）。
- **逻辑关系：**总分、问题分解；跨层组织研究应对。
- **逻辑结构：**`总问题⊃{机制问题，方法问题，验证问题}；问题层→研究动作层→验证／目标层〔应对，不默认逐项配对〕`。
- **适用场景：**科学问题凝练、研究缺口、研究对象复杂性、从问题到研究思路的总览。
- **视觉结构：**顶部总问题；下方分区表达问题层级或不同问题角色；可用左侧层级标签、上下层带或一主多辅卡片承载研究应对。
- **案例来源：**N07、N15、N18、N26；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**先用分区区分不同角色，再在各层内部并列。问题名称宜保持同一抽象程度，研究动作说明如何回应问题，验证层说明什么结果才算解决。
- **复用边界：**与T07的同级三个问题区分；本型允许机制、方法、验证处于不同层次。不能只因上下排列就宣称严格依赖，也不能只因数量相同就配成问题—方法映射。复杂度过高时拆页。

<a id="t39"></a>
## 页面类型39：资源平台与任务保障

- **名称：**资源平台与任务保障（T39）。
- **逻辑关系：**资源—能力映射、可行性论证；资源可分类。
- **逻辑结构：**`{资源Ri↔能力Ci}→任务可实施〔支撑〕`。
- **适用场景：**研究基础、实验条件、设备平台、项目可行性、合作保障。
- **视觉结构：**照片型：顶部能力总述，中部资质／核心设备，底部设备图册；表格型：平台类别—平台名称—核心能力，多行对齐。
- **案例来源：**W11、W13；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**资源名称负责可核查，能力字段负责解释用途，任务字段负责与本项目关联。核心资源加大，辅助资源统一尺寸；表格用行对齐降低查找成本。
- **复用边界：**与T21的分类数量统计不同，重点是资源能保障什么。平台照片不证明设备性能，需用参数或可核查条件支持；仅有设备清单时应补本项目具体用途。

<a id="t40"></a>
## 页面类型40：成果摘要与代表作清单

- **名称：**成果摘要与代表作清单（T40）。
- **逻辑关系：**总分、清单支撑；成果属性按行映射。
- **逻辑结构：**`成果概述→{代表作1，…，代表作N}〔举例支撑〕；每项↔{来源，年份，贡献角色}`。
- **适用场景：**学术论文、专利、成果汇总、个人研究基础。
- **视觉结构：**顶部一句成果概述；主体全宽表格；列承载来源、题目、年份、贡献角色；用少量强调色定位重要贡献。
- **案例来源：**W02；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**概述提供规模和研究方向，清单提供可核查实例。统一作者角色与年份的格式，限制长题目的换行，让读者能横向核对同一成果。
- **复用边界：**总量和展示条数可以不同，但须说明“代表作选录”。作者身份的统计口径必须一致。与T16的实验评价证据矩阵不同，本型呈现科研产出而非实验结论。

<a id="t41"></a>
## 页面类型41：双目标协同与约束支撑

- **名称：**双目标协同与约束支撑（T41）。
- **逻辑关系：**并列目标、共同约束、协同支撑。
- **逻辑结构：**`{目标A∥目标B}←{支撑路径、共同约束}；{A，B}→综合目标〔协同〕`。
- **适用场景：**性能与可靠性、精度与适应性、两个主要设计目标共同成立的方案框架。
- **视觉结构：**顶部总目标；左右两个目标区；中央共同对象或共享瓶颈；两侧分别放支撑技术，底部共同工况与综合指标。
- **案例来源：**N17；点击案例编号可查看原文件、逐图分析与选用条件。
- **设计原则：**对称布局强调两个目标都重要，中央公共区解释共同瓶颈，底部共同条件防止读者把两路看成互不相干的项目。
- **复用边界：**双目标不等于对比，也不自动构成权衡；只有明确收益—代价关系才归为权衡。N17中心循环箭头未明确反馈变量，复用时宜改成有语义的协同连接。
